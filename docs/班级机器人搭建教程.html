班级晚点名 QQ 机器人
搭建教程

群里 @机器人 查未点名 → 自动回复未报名单，并 直接 @ 到没点名的宿舍长
面向零编程基础的班长｜预计 60～90 分钟｜全程使用免费额度
项目仓库：github.com/VeniceJiaozi/Auto-Dormitory-Check-for-NJU
技术栈：Python 标准库 + QQ 开放平台官方 Bot API + 腾讯云函数 SCF + 南大表格（SeaTable）
教程版本 v1.0（2026-09-20）｜由 2026 级技科 7 班实测记录整理

写在前面：你会得到什么、需要准备什么

做完之后：班里任何同学在群里 @机器人 查未点名（或 点名），机器人 1 秒左右回复两条消息——第一条是未报/异常宿舍的文字名单，第二条把没点名的宿舍长逐个真 @ 出来（对方收到红点提醒）。同学也可以 @机器人 帮助 看用法。

准备清单

需要的东西说明 / 没有的话怎么办
一个 QQ 群，且你是群主或管理员机器人只能被邀请进自己管理的群。
能上网的电脑（Windows / Mac 都行）需要浏览器 + 命令行（后面每条命令都给了复制粘贴版本）。
Python 3.9 或更新只用于跑测试和打包，机器人本体跑在腾讯云上，不在你电脑上。没有 Python 也能照做，但会少一层自检。
腾讯云账号（用 QQ 登录即可）免费额度足够；本教程不开通任何收费产品。
你们班的晚点名表（南大表格 SeaTable）最关键的一项，见下一节。如果学院已有全院统一的点名表，需要向表格所有者要一个「外部应用」查看链接。
QQ 开放平台注册机器人（约 10 分钟）需要实名手机号；要让全班正常使用还需完成个人主体认证。
先说三个"做不到"，免得你走弯路： ① 机器人只能收到 @ 了它 的消息，看不到群里其他聊天内容； ② 它不能主动定时播报（本教程不含该功能，且受平台权限限制）； ③ 点名表的访问令牌约 3 天过期，需要你每 3 天左右复制粘贴更新一次（约 2 分钟，机器人也会在名单快过期时自动提醒你）。

第 0 步　看懂整条链路（3 分钟，很重要）

同学群里发：@机器人 查未点名
        ↓
【QQ 开放平台】① 把这条事件推给你的云函数地址（Webhook）
        ↓
【腾讯云函数 SCF · bot.py】
        ├─ ② 带着令牌去查点名表 ↓
        │        【南大表格 SeaTable】返回全部宿舍行 → 分成"未报 / 异常"
        └─ ③ 把名单 + @ 发回群里 ↑

所以一共要配三个东西：QQ 开放平台（知道往哪推）、云函数（真正干活）、点名表接口（数据从哪来）。三者靠 5 个环境变量串起来，全部配置都在网页上完成，不需要改一行代码。

代码已经写好在仓库里，目录长这样：

文件作用
src/bot.py云函数入口：验签、路由指令、发两条回复
src/api.py查点名表 + 分类未报/异常 + 算令牌余量
src/qq_sender.py取 access token、往群里发消息
src/ed25519.py回调验签用的签名算法（纯标准库，无需安装任何东西）
tests/、local_e2e.py离线测试与本地联调（不会真的往群里发消息）

第 1 步确认你们班的点名表能被读取

机器人不碰你班那张表的写入权限，只读。它靠"列名前缀"认列，因此你们班的表只要有下面 5 列、且列名以这些词开头就能直接用（列的先后顺序无所谓，列的 ID 变了也无所谓）：

必须存在的列名（前缀匹配）示例值机器人怎么用它
宿舍号南二-425名单里显示的主键
宿舍长姓名张三名单里括号中的名字
宿舍长学号261880001绑定身份的唯一依据，必须准确
当日日期2026-09-20T00:00:00+08:00不是今天 / 为空 = 未报
当日晚点名情况全部到位 / 未全部到位不等于「全部到位」= 异常，原文展示
如果你们班表里的列名是「晚点名情况」「宿舍长」之类的其他叫法，两种解决办法：① 把列名改成上表的写法（推荐，改一次就好）；② 改 src/api.py 里 _keymap() 的几个前缀字符串（一行一处）。

1.1 拿到三个参数

  1. 用浏览器打开你们班的晚点名查询应用页面（SeaTable 的 custom app 链接，形如 https://table.nju.edu.cn/apps/custom/<你的应用>/?page_id=XXXX），需要南大统一身份认证登录。
  2. 按 F12 打开开发者工具 → 切到 Network（网络） 标签 → 刷新页面 → 找到那条请求地址里含 universal-apps/ 的接口（点开它，能看到 "success": true 和一堆行数据）。
  3. 从这条请求里抄下两样东西：接口 URL（到 /rows/ 为止，不含问号后面）和 page_id= 后面的那串。
  4. 再取访问令牌：切到 Console（控制台）标签，粘贴执行下面这行，令牌就进剪贴板了： 
    copy(document.documentElement.outerHTML.match(/accessToken:\s*'([^']+)'/)[1])
自检：在 Console 里执行下面两行，能看到 "success":true 说明令牌和 URL 都对了（把 URL、PAGE、TOKEN 换成你抄到的值）： 
fetch("URL?page_id=PAGE&start=0&limit=3",{headers:{Authorization:"Token "+"TOKEN"}})
  .then(r=>r.json()).then(d=>console.log(d.success, d.results.length))

令牌有效期约 3 天。它过期后机器人会在群里回「点名数据查询失败」，重取一次填进环境变量即可。

第 2 步在 QQ 开放平台建一个机器人

  1. 打开 bot.q.qq.com（QQ 开放平台）→ 登录 → 创建机器人。名称、头像、简介自便（例：「XX班点名助手」）。
  2. 进入机器人后台 → 开发设置，抄下 AppID 和 AppSecret。AppSecret 等于密码，别发群、别截图给别人、别写进代码。
  3. 同一页把「接入方式」选 Webhook，回调地址先留空——它要等第 4 步云函数建好才有值（平台保存时会立刻向该地址发一次验证请求，所以顺序不能颠倒）。
  4. 如需让全班同学都能用，去「后台设置 / 主体信息」完成个人主体认证（要实名手机号 + 身份证）。实测：未认证不影响你自己群里 @ 它拿回复，但会锁住「服务范围」，面向全班正式发布前必须认证。

第 3 步下载代码，本地跑一遍测试

打开命令行（Windows：Win+R 输入 cmd；Mac：终端），逐行执行：

git clone https://github.com/VeniceJiaozi/Auto-Dormitory-Check-for-NJU.git
cd Auto-Dormitory-Check-for-NJU
python -m unittest discover -s tests
看到 Ran 40 tests in ... 和 OK 就说明代码没问题（测试全离线，不会调用任何真实接口、不会发消息）。

然后建一份自己的配置。用记事本打开 config/.env.example，另存为 config/.env，把等号右边填上你的值：

QQ_BOT_APP_ID=你的AppID
QQ_BOT_APP_SECRET=你的AppSecret
ROLLCALL_API_URL=https://table.nju.edu.cn/api/v2.1/universal-apps/你们的ID/rows/
ROLLCALL_PAGE_ID=你的page_id
ROLLCALL_API_TOKEN=刚复制的令牌
.env 已被仓库的 .gitignore 排除，永远不要把它提交或发到群里。说明：.env.example 里的默认 URL/page_id 指向的是本班的点名表，你换了班级一定要改成自己应用的值（第 1 步抄下来的那两行）。
机器人改了名字不用动代码：QQ 把 @ 传成 <@!数字> 这种标记，src/bot.py 里的 MENTION 正则会先把它整段去掉再比对指令，跟机器人叫什么无关。

第 4 步部署到腾讯云函数 SCF

4.1 打包

在项目根目录执行（PowerShell 用 Compress-Archive，或直接用 Python 一行）：

python -c "import zipfile,os; z=zipfile.ZipFile('deploy/rollcall_bot.zip','w',zipfile.ZIP_DEFLATED); [z.write(os.path.join('src',f),f) for f in ['bot.py','api.py','qq_sender.py','ed25519.py']]; z.close(); print(os.path.getsize('deploy/rollcall_bot.zip'))"

⚠️ 关键：zip 根目录要直接是 bot.py、api.py……，不能包一层 src/ 文件夹，否则函数找不到入口。仓库里已带一份 deploy/rollcall_bot.zip，改了代码就按上面重新生成。

4.2 新建函数

  1. 腾讯云控制台 → 云函数 SCF → 地域选 广州 → 新建 → 从头创建。
  2. 填写：函数类型 事件函数｜名称如 rollcall-bot｜运行环境 Python 3.9｜执行超时时间 10 秒｜内存 128MB｜提交方法选 本地上传 zip 包（选中后才会出现上传按钮）｜函数入口 bot.main_handler。
  3. 权限：不用选任何运行角色（函数不出网访问你的云资源）。
  4. 创建完成后，在「函数配置」里核对：公网访问为已启用（要访问 table.nju.edu.cn 和 QQ 接口）。

4.3 填环境变量

「函数配置 → 编辑 → 环境变量」，把第 3 步 .env 里那 5 行原样填进去（键名完全照抄，大小写敏感）。保存。

第 6 步做「直接 @」时还会再加第 6 个变量 QQ_ROSTER_JSON，现在不用管。

4.4 开一个「函数 URL」当回调地址

  1. 函数详情页 → 函数 URL → 创建。不要用「API 网关触发器」，该入口 2024-07 起已不可新建。
  2. 访问类型 公网访问、授权「开放」；务必勾选 「参数兼容」（不勾的话函数读不到 QQ 推来的原始 JSON，机器人会永远"没反应"）。
  3. 创建后得到形如 https://xxxx.ap-guangzhou.tencentscf.com 的地址，复制备用。

第 5 步先自测，再回 QQ 平台填回调

5.1 命令行自测（模拟一次 @ 机器人）

python -c "import json,urllib.request as u; b={'id':'t','op':0,'t':'GROUP_AT_MESSAGE_CREATE','d':{'group_openid':'GROUP','content':'查未点名','author':{'member_openid':'S'},'id':'M1'}}; r=u.Request('https://你的函数URL',data=json.dumps(b).encode(),headers={'Content-Type':'application/json'},method='POST'); print(u.urlopen(r,timeout=20).read().decode())"
期望输出：{"replied": "rollcall", "pending": 数字, "sent": [false, false]}。
pending 有数字 ⇒ 点名表读通了。sent:[false,false] 是正常的（我们故意用了假群号，发不出去）。若 pending=0 或报 api error，见第 7 步排查。

另一个不用命令行的办法：SCF 控制台「函数代码 → 测试」面板，事件内容填 {"body": "{\"op\":0,\"t\":\"GROUP_AT_MESSAGE_CREATE\",\"d\":{\"content\":\"查未点名\",\"group_openid\":\"G\",\"author\":{\"member_openid\":\"S\"},\"id\":\"M1\"}}", "isBase64Encoded": false}， 点「测试」后右侧执行日志会打印函数里所有 print——这是不开通日志服务也能看到内部过程的关键技巧。

5.2 回 QQ 开放平台保存回调地址

  1. 把函数 URL 填进「开发设置 → 回调地址」，接入方式选 Webhook，保存。
  2. 平台保存时会向你的地址发一次 op=13 验证请求，通过即显示「校验成功」。若提示 40001 签名校验不通过 / 40002 回调地址状态同步失败，通常是云端签名超过了平台的 3 秒超时——本仓库已内置快速签名实现（约 0.2 秒），若仍失败请把函数内存调到 256MB 再试。
  3. 再到「接收事件配置」把订阅方式设为 全部接收（至少要有 GROUP_AT_MESSAGE_CREATE）并保存。刷新页面确认还是"全部接收"——保存失败时页面会静默退回"部分接收 0/51"，这个坑非常迷惑人。

5.3 把机器人请进群

在 QQ 群的群机器人管理里添加你的机器人（或用后台生成的邀请链接）。进群后 @机器人 查未点名，第一次就要看到名单回复。

到这里，"能用"就已经全部搞定了。下面第 6 步是它最有价值的部分——被点名的宿舍长会被直接 @ 到。

第 6 步开启「直接 @ 未报宿舍长」（10 分钟，可选但强烈推荐）

原理：QQ 只给了机器人一串群内匿名 ID（member_openid），它不是 QQ 号、也无法从接口批量导出（成员列表接口需向平台申请白名单）。所以只能请每位宿舍长自己 @ 机器人一次，机器人回给你一串对应关系，你抄进云函数即可。

  1. 在班群发通知： 
    @你们的机器人 绑定 你的学号
（例如：@点名助手 绑定 261880001，「绑定」和学号之间有没有空格都行）
  2. 机器人会回三行，最后一行形如 261880001=1111111111111111111111111111AAAA（右半边是那位同学的 32 位群内标识）。它已经核对过：这个学号在你们班点名表里确实是某宿舍的宿舍长，且是本人发的；学号不存在它会直接说明。
  3. 把这些「学号=openid」交给 AI 助手（或自己整理）成下面这个 JSON，填到云函数环境变量 QQ_ROSTER_JSON 并保存： 
    {"261880001":"1111111111111111111111111111AAAA","261880002":"2222222222222222222222222222BBBB"}
  4. 群里再发一次 @机器人 查未点名：未报的宿舍长会被蓝色 @、收到红点提醒；还没绑定的会以「宿舍号（姓名）」列在后面，一条都不会漏。
换宿舍长 / 新同学怎么办？让新人发一次「绑定 本人学号」，把新的那一行加进 QQ_ROSTER_JSON 保存即可。只改环境变量，不用改代码、不用重新部署。

第 7 步日常运维与故障排查

7.1 每 3 天换一次点名令牌（约 2 分钟）

机器人会在余量不足 48 小时时，自动在「查未点名」回复末尾加一行提醒。看到提醒就照第 1.1 节重新复制令牌，替换云函数环境变量 ROLLCALL_API_TOKEN，保存即生效。

7.2 排查表（按"最可能"排序）

现象最可能的原因怎么办
群里 @ 它完全没反应QQ 平台侧根本没推过来（回调地址没保存成功 / 事件没订阅 / 机器人不在群里）看 SCF「监控 → 分钟级调用次数」：那个时刻有 1 次调用 = 平台推到了，问题在函数里；0 次 = 回第 5.2 步，重新保存回调地址与"全部接收"，并刷新页面确认真的存住了。
有 1 次调用但耗时只有 1 毫秒、群里无回复事件没匹配上任何分支（最常见是把事件类型字段写成了 type——官方信封里是 t）确认函数代码是仓库最新版；别信自己拼的测试数据，以 bot.q.qq.com 文档页的字段名为准。
回复了但 @ 显示成一串英文代码@ 标签只在 markdown 消息（msg_type=2）里才会渲染成蓝色 @，纯文本里就是原样显示用本仓库代码即已走 markdown；自行改动时别把第二条回复换成纯文本。
名单是空的 / pending=0令牌过期，或列名与第 1 步要求不符，或 ROLLCALL_API_URL/PAGE_ID 填错先看函数执行日志：HTTP 403 = 令牌过期；metadata 缺少「宿舍号」列 = 列名不对。
「绑定」发了没反应用班长自己的学号测（班长学号通常不在"宿舍长学号"列）；或消息被当无关内容忽略换真正的宿舍长学号；@ 时要把机器人点选成蓝色名片，手打名字无效。
改了代码没生效只重新打包没重新上传，或上传的 zip 里多了一层 src/控制台「函数代码 → 本地上传 zip 包」重新传一次；注意「提交方法」下拉每次都会退回"在线编辑"，要先选"本地上传 zip 包"再选文件。
保存 QQ 后台设置时提示 40001/40002平台保存时会重新验签，签名耗时超了 3 秒内存调到 256MB 后重试；重试前先点一次"测试"确认函数能正常返回。

7.3 三条硬规矩

  • 凭据只走环境变量：AppSecret、访问令牌、同学 openid 一律不写进代码、不提交进仓库、不发到群里。
  • 只用 QQ 开放平台官方 Bot API：任何"第三方协议库/插件"都可能造成封号，本项目一行都不用。
  • 不要为"方便调试"随意开通计费产品：日志服务 CLS、COS 等都是按量收费，本项目的免费额度足够；不看不影响运维（用 5.1 的控制台测试面板即可）。

第 8 步费用与合规（一句话结论：基本不花钱）

项目费用
QQ 开放平台 Bot API免费，仅有调用频率限制。
南大表格（SeaTable）接口免费（校内自有实例）。代价只是令牌约 3 天要换一次。
腾讯云函数 SCF每月免费额度（调用次数 + 内存×时长）远够用。实测：128MB × 约 0.5～2 秒/次，全班每天几十次，一个月用量比免费额度低三四个数量级。本仓库实测账号连续三月账单 0.00 元。
会花钱的情形开通日志服务 CLS、COS、NAT/固定公网 IP、NAS，或把内存/超时调很大且高频调用。教程不涉及，动手前请先看清计费提示。

合规提醒：「宿舍长学号 + 姓名 + 是否到位」属于同学个人信息，只在班级群内展示、不要导出到公网；QQ_ROSTER_JSON 里的 openid 是 QQ 群内匿名标识，但同样按个人信息对待，只存在云函数环境变量里。面向全班正式发布前，请完成 QQ 开放平台的个人主体认证并按平台要求提交审核。

附录 C　开发时踩过的坑（省你一天）

  1. 事件类型字段是 t 不是 type；写错的表现是"函数被调用、1 毫秒返回、群里毫无反应"。
  2. QQ 的 HTTPError 字符串里没有错误原因，真正的 code/message 在响应体里；不读出来就永远查不到为什么没发出去（本仓库已处理）。
  3. 平台的 access token 是全平台共享的一张票在倒数（实测约 50 分钟），不是每次调用都给新的 7200 秒；别拿"我调试时把它的票顶掉了"解释偶发失败。
  4. 平台会自动给每条被动回复加 @触发者 前缀，判断"我们的 @ 有没有生效"时要把它排除掉。
  5. 被动回复的 msg_id 只有 5 分钟有效、最多回 5 条（msg_seq 1~5）；所以机器人不能靠"事后补发"提醒。
  6. QQ 号不能直接换算成 member_openid，官方也没有转换接口——这就是第 6 步必须让每人自己发一次"绑定"的唯一原因。
  7. SCF 的 API 网关触发器已不可新建，用「函数 URL」并勾选参数兼容。
  8. 控制台与 QQ 开放平台的网页登录态约 1 小时过期，重登要本人扫码；操作前先看还在不在登录态。

本教程由技科 7 班实测记录整理，配置项与接口行为以 bot.q.qq.com、cloud.tencent.com/document、seatable.cn 官方文档及你所在校的表格实际情况为准。遇到问题把机器人回复原文和函数「执行日志」贴给 AI 助手即可定位。祝顺利。
